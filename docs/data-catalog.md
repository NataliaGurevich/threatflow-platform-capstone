# ThreatFlow data catalog

## Conventions

- All timestamps are stored as timezone-aware values and interpreted in UTC.
- `cve_id` is validated as `CVE-<year>-<sequence>` and is the analytical join key.
- Acquisition time, source-effective time and database update time have different meanings
  and must not substitute for one another.
- Cross-source relationships are intentionally logical rather than foreign keys: normal
  differences in source coverage must not block ingestion.

## Source datasets

### NVD CVE API 2.0

**Owner:** NIST National Vulnerability Database.  
**Grain:** one API item is the NVD representation of one CVE at response time.  
**Natural key:** `cve.id`; source ordering/version field: `cve.lastModified`.  
**Update pattern:** continuously published and modified; retrieved through bounded published
or modified windows with pagination.

| Source field | Type | Meaning and project treatment |
| --- | --- | --- |
| `cve.id` | string | CVE identifier; maps to `nvd_cves.cve_id` |
| `cve.descriptions[]` | array | English description preferred; another valid description is fallback |
| `cve.published` | timestamp | Original publication time; not a modification checkpoint |
| `cve.lastModified` | timestamp | Source version ordering and incremental modified-window field |
| `cve.metrics` | object | Project selects valid CVSS 4.0, then 3.1, 3.0, then 2.0; PRIMARY preferred |
| `cve.weaknesses[]` | array | Project extracts distinct `CWE-*` identifiers |
| `cve.references[]` | array | Preserved as JSON for investigation context |
| `startIndex` | integer | Zero-based page offset |
| `resultsPerPage` | integer | Page size reported by the API |
| `totalResults` | integer | Expected result total; changes during traversal cause failure |

Known limitations: CVSS/CWE may be absent or delayed; records are mutable; rejected CVEs
remain identifiable; older records do not necessarily have modern CVSS versions.

### CISA Known Exploited Vulnerabilities

**Owner:** US Cybersecurity and Infrastructure Security Agency.  
**Grain:** one vulnerability entry in a complete current catalog snapshot.  
**Natural key:** `cveID`; snapshot identity: exact-content SHA-256 or official Git commit.  
**Update pattern:** irregular complete-snapshot replacement; Git mirror updates after the
canonical catalog.

| Source field | Type | Meaning and project treatment |
| --- | --- | --- |
| `catalogVersion` | string | Optional upstream snapshot revision metadata |
| `dateReleased` | date/string | Catalog release metadata; not the per-record addition date |
| `count` | integer | Declared count; must equal the actual vulnerabilities array length |
| `vulnerabilities[].cveID` | string | CVE identifier and current-table primary key |
| `vendorProject` | string | Vendor or project named by CISA |
| `product` | string | Affected product named by CISA |
| `vulnerabilityName` | string | CISA vulnerability title |
| `dateAdded` | date | Date the CVE entered KEV |
| `shortDescription` | string | Short CISA description |
| `requiredAction` | string | Required remediation action |
| `dueDate` | date | CISA remediation due date context |
| `knownRansomwareCampaignUse` | string | CISA ransomware association value; not inferred by ThreatFlow |
| `notes` | nullable string | Optional notes/reference text |

Known limitations: the feed is current state, not a historical API; absence from a new
snapshot is not accepted as a deletion without validation; vendor/product strings are not
normalised asset identifiers.

### FIRST EPSS daily scores

**Owner:** FIRST EPSS SIG; scores generated by Empirical Security.  
**Grain:** one CVE on one source score date.  
**Natural key:** `(cve, score_date)`.  
**Update pattern:** complete daily compressed CSV plus dated historical archives.

| Source field | Type | Meaning and project treatment |
| --- | --- | --- |
| `cve` | string | CVE identifier |
| `epss` | decimal in `[0,1]` | Estimated exploitation probability during the following 30 days |
| `percentile` | decimal in `[0,1]` | Relative rank, not probability; derived only for legacy files without it |
| header `score_date` | date | Source-effective date; must match the requested date |
| header model version | string | Methodology version metadata; version boundaries can shift the series |

Known limitations: publication may lag the beginning of the UTC score date; a syntactically
valid small file may be incomplete; EPSS is neither impact nor organisational risk.

## Application and control tables

| Table | Grain and key | Purpose | Update/retention behavior |
| --- | --- | --- | --- |
| `nvd_cves` | Latest record per `cve_id` | Searchable current NVD state and CVSS/CWE/reference enrichment | Conditional UPSERT; an older `last_modified` cannot replace a newer row |
| `cisa_kev_vulnerabilities` | Latest accepted KEV entry per `cve_id` | Current confirmed-exploitation/remediation context | Idempotent UPSERT; missing snapshot entries are not physically deleted |
| `cisa_kev_changes` | One CVE event per `(commit_sha, cve_id)` | Baseline/added/modified/removed history derived from valid snapshots | `revision_type` distinguishes Git commit and content SHA-256 revisions |
| `epss_scores` | One row per `(cve_id, score_date)` | Detailed recent EPSS history | Retains the configured number of inclusive source dates, 30 by default |
| `epss_current` | Latest score per `cve_id` | Fast current-score joins | Older backfills cannot regress `score_date` |
| `epss_daily_summaries` | One aggregate per `score_date` | Long-lived daily counts and score/risk aggregates | Retained after detailed rows age out |
| `raw_artifacts` | One manifest row per `(source, sha256)` | Logical Raw identity, request metadata and observations | Re-observation updates `last_seen_at`/`seen_count`; bytes are not overwritten |
| `raw_artifact_locations` | One current location per `(artifact_id, backend)` | Verified local and/or S3 physical copies | Location re-verification updates locator/version and `last_verified_at` |
| `ingestion_checkpoints` | One row per `source` | Durable successful coverage boundary | NVD checkpoint advances only after a complete successful commit |

## Important application fields

### `nvd_cves`

| Field | Database type | Nullable | Definition |
| --- | --- | --- | --- |
| `cve_id` | `varchar(32)` | no | Primary key and cross-source analytical key |
| `description` | text | yes | Selected human-readable description |
| `published` | timestamptz | yes | NVD publication time |
| `last_modified` | timestamptz | yes | NVD source version used for stale-update prevention |
| `cvss_version` | `varchar(16)` | yes | Project-selected CVSS version |
| `cvss_score` | float | yes | Base score; technical severity, not risk |
| `cvss_severity` | `varchar(16)` | yes | Source severity label when available |
| `cvss_vector` | text | yes | CVSS vector string |
| `cwe_ids` | JSONB | yes | Distinct CWE identifiers |
| `references` | JSONB | yes | NVD reference objects |

### `raw_artifacts`

| Field | Database type | Definition |
| --- | --- | --- |
| `source`, `sha256` | string | Unique content identity within a source |
| `storage_path` | text | Legacy first locator retained for compatibility; active reads use locations |
| `first_acquired_at`, `last_seen_at` | timestamptz | First storage and latest observation times |
| `seen_count` | integer | Number of committed manifest observations |
| `request_mode` | string | Examples: snapshot, published, modified, git history |
| `requested_start`, `requested_end` | timestamptz | Source request interval where applicable |
| `page_start_index` | integer | NVD page offset where applicable |
| `record_count` | integer | Validated projected record count when known |
| `ingestion_run_id` | string | Airflow run lineage when available |
| `source_revision` | string | Upstream Git/source revision when applicable |

### `raw_artifact_locations`

| Field | Database type | Definition |
| --- | --- | --- |
| `artifact_id` | bigint FK | Logical artifact in `raw_artifacts`; cascades on artifact deletion |
| `backend` | string | Storage implementation (`local` or `s3`) |
| `uri` | text | Local path or `s3://bucket/key` locator |
| `storage_bucket`, `storage_key` | nullable string/text | Required structured locator values for S3 rows |
| `storage_version_id` | nullable text | S3 version returned by a versioned bucket |
| `first_recorded_at`, `last_verified_at` | timestamptz | Location discovery and latest successful verification times |

The `threatflow-reconcile-raw-storage` command selects local locations without an S3 peer.
Dry-run validates size and SHA-256 without AWS calls. Apply mode records an S3 location only
after the adapter has verified the stored object's checksum and metadata; it does not change the
logical artifact's `seen_count`.

For new ingestion, optional validated replication records both local and S3 locations in the
same manifest transaction and still increments `seen_count` once. Local storage occurs before
parsing so rejected bytes remain available for diagnosis. S3 is an accepted Bronze location:
only payloads that pass all source-specific validation and completeness checks are promoted.

## Relationships and quality interpretation

- `nvd_cves.cve_id`, `cisa_kev_vulnerabilities.cve_id`, `epss_current.cve_id`,
  `epss_scores.cve_id` and `cisa_kev_changes.cve_id` may be joined analytically.
- No database foreign key is imposed between source tables because each publisher has a
  different scope and publication schedule.
- `raw_artifacts` owns zero or more physical `raw_artifact_locations`, but is not a parent table
  for every normalized business row; request metadata can cover a page or complete snapshot.
- `ingestion_checkpoints` describes source-window coverage, not row-level lineage.
